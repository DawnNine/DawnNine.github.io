Windows运行程序流程

1、验证并解析 PE 文件

Windows加载器首先读取 DOS 头、PE 签名、文件头、可选头，验证文件是否合法，提取映像大小、入口点、节表信息等。

2、创建进程对象和虚拟地址空间

内核创建 EPROCESS、句柄表、进程工作集，并为新进程分配一块完整的用户态虚拟地址空间。

3、将 EXE 映射到内存（重点）

根据 PE 节表，使用内存映射文件（Section Object）将 EXE 的各个节（.text, .data 等）映射到虚拟地址空间中。此时磁盘文件并未全部读入，由页错误按需调页。

4、应用 ASLR 和重定位

映像基地址是编译器/链接器的默认配置，32位EXE：0x00400000，32位DLL：0x10000000；64位 EXE：0x0000000140000000；64位DLL：0x0000000180000000。当开启了ASLR ，系统加载的时候就会忽略映像基地址，随机选择一个地址，程序中基于默认映像基地址生成的将会通过重定位表进行修复。

5、加载依赖的 DLL

递归解析 EXE 的导入表，找到每个需要的 DLL，同样对它们进行映射、ASLR/重定位处理。这会形成一棵依赖树，加载器保证所有模块都就位。

6、解析导入函数并修复 IAT（重点）

遍历 EXE 及所有 DLL 的导入表，从对应 DLL 的导出表查找函数地址是基于重新修复后映像基地址，填入调用方的导入地址表 (IAT)。此后调用这些 API 才能正确跳转。

7、初始化进程运行环境

系统填充 PEB（进程环境块），设置进程堆（默认堆）、命令行、环境变量、当前目录、标准句柄等，并准备主线程的栈和初始上下文。

8、 执行 TLS 回调和 DLL 初始化

调用 PE 中 TLS 目录指定的所有 TLS 回调函数，然后按照依赖顺序，依次调用所有已加载 DLL 的 DllMain 函数，传入 DLL_PROCESS_ATTACH。
TLS 回调发生在 DllMain 之前，这个特性经常被利用来做早期初始化和反调试。

9、转入程序入口点

一切就绪后，主线程从 EXE 的入口点（PE 头中的 AddressOfEntryPoint）开始执行。通常是 CRT 的启动函数（如 mainCRTStartup），它再初始化 C 运行时库、调用全局构造器，最终调用你的 main 或 WinMain。

加壳原理

压缩/加密：对原始程序的代码段、数据段等关键部分进行压缩或加密，使其变成一堆“乱码”。

植入外壳：生成一个外壳程序，并将加密/压缩后的原始程序数据作为一部分附加在这个外壳程序后面。

修改入口点：修改生成的可执行文件的“程序入口点”（OEP, Original Entry Point），使其指向外壳程序的代码，而不是原始程序的代码，当外壳代码执行结束后，会自动跳转到原程序的入口点。

节处理

首先分析对节的处理pack函数对传入的文件进行处理，其中有pack1()、pack2()、pack3()、pack4()四个关键函数，其中pack2()函数是对节具体处理。

pack2()函数作用将文件分成多个块进行处理后，交给compressWithFilters()函数对各个块进行处置。

compressWithFilters() 函数是用来找到最佳的压缩方法prepareMethods()和过滤器prepareFilters()，并执行实际的压缩操作的一个核心函数，并根据选择的压缩方法和过滤器生成Stub。

prepareMethods()压缩方法和prepareFilters()过滤器进行遍历压缩比对，选择最优的压缩算法。

程序在运行中的原理，INT和IAT表起到的作用，INT是在程序加载的时候真正要去内存中找到的位置，比如说MessageBoxA，他是根据INT表写入到内存中的位置，函数真正调用MessageBoxA是直接去内存中进行调用，不是先去找INT表进行挨个遍历查询相关位置。
