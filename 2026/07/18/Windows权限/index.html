Windows权限

令牌

Windows 权限体系是以访问令牌为中心的。令牌携带了所有身份和权限信息，内核在每次资源访问时都通过令牌来判断。没有令牌，就没有权限判断的依据，令牌的权限判断是由Lsass来进行判断。

访问令牌

​ 访问令牌包含登录会话的安全信息。 当用户登录时，系统会创建一个访问令牌，并且代表该用户执行的每个进程都拥有该令牌的一个副本。 该令牌标识用户、用户所属组和用户的特权。 系统使用该令牌控制对可保护对象的访问，并控制用户在本地计算机上执行各种系统相关操作的能力。 有两种访问令牌，即主令牌和模拟令牌。

访问令牌（AccessToken） 两种类型

  • Delegation Token：授权令牌，也叫主令牌，通常可由 Windows 内核创建的访问令牌。 可以将其分配给进程，以表示该进程的默认安全信息。
  • Impresonation Token：模拟令牌，已创建用于捕获客户端进程安全信息的访问令牌，允许服务器在安全操作中“模拟”客户端进程。

Token继承关系

每个进程创建时都会根据登录会话权限由 LSA(Local Security Authority) 分配一个Token，如果在调用CreateProcess时显式指定了一个Token，则使用该Token；否则，新进程将默认继承其父进程的Token。（很多杀软会基于这个继承关系来查杀）

lsass.exe身份校验

lsass.exe（Local Security Authority Subsystem Service）是 Windows 操作系统中的一个重要进程，负责处理安全策略、用户身份验证、登录会话管理和访问控制等任务。它是一个关键的系统进程，任何与身份验证相关的操作都会通过 lsass.exe 来进行，因此它涉及大量的安全日志和痕迹。

  1. 功能：lsass.exe 负责管理本地安全策略、用户认证、访问控制和密码策略等安全相关的功能。它是Windows操作系统的一个核心组件，用于确保系统的安全性和稳定性。
  2. 认证和授权：lsass.exe 通过执行各种认证和授权操作，确保用户和进程的身份验证和授权。例如，当用户登录时，lsass.exe 负责验证用户提供的凭据，并授予相应的权限和访问权限。
  3. 密码管理：lsass.exe 还负责管理用户的密码策略，包括密码复杂性要求、密码过期策略等。它存储和加密用户的凭据，并确保密码的安全性和可靠性。
  4. 安全通信：lsass.exe 还负责管理安全通信机制，包括与其他系统组件和网络服务之间的安全通信。它确保数据在传输过程中的完整性和保密性，防止数据被篡改或窃取。
  5. 重要性和安全性：由于 lsass.exe 负责处理系统的安全相关功能，因此它是系统中的一个关键组件。任何对 lsass.exe 的非法访问或者攻击都可能导致系统的安全风险，例如身份盗窃、密码泄露等。因此，确保 lsass.exe 进程的安全性和稳定性对于系统的整体安全至关重要。

UAC(User Account Control)

UAC 的全称是 User Account Control，中文译为“用户账户控制”。它是从 Windows Vista 开始引入的一项核心安全功能，并一直延续至今（包括 Windows 7, 8, 10, 11）。
UAC的核心目标是：防止恶意软件在未经你许可的情况下，对系统进行未经授权的更改。

UAC 的双令牌机制

Windows用户登录使用的账户都是在管理员群组中，但是Windows 实际上为你创建了 两个令牌：完整管理员令牌、过滤令牌 (Filtered Token)。

标准用户模式（默认状态）：

  • 当你登录系统后，即使你是管理员，系统和大多数程序也会默认在“标准用户”权限下运行。在这个模式下，程序只能访问和修改当前用户的数据（如“文档”、“桌面”），无法触及系统核心区域（如 C:\Windows、注册表关键位置等）。

管理员权限提升（需要时触发）：

  • 当某个程序或操作需要修改系统设置、安装软件或访问受保护的区域时，它就需要更高的权限。此时，UAC 就会介入，弹出一个确认对话框，要求你（用户）明确批准这个操作。这个过程被称为“权限提升”（Elevation）。

Protected Process Light (PPL) Attack

Windows从 vista 版本引入一种进程保护机制(Process Protection)，用于更进一步的控制进程的访问级别，在此之前，用户只需要使用SeDebugPrivilege 令牌权限即可获取任意进程的所有访问权限；随后 Windows8.1 在此进程保护的基础上，扩展引入了进程保护光机制(Protected Process Light)，简称 PPL 机制，其能提供更加细粒度化的进程访问权限控制。

这个可以理解成system权限精细化分，system权限之间有差别，使用底权限system无法打开高权限的system，部分机器上运行Mimikatz，使用的是system权限并且开启了SeDebugPrivilege，但是无法获取到lass程序的句柄，抓取不到程序内存。（使用procexp可以看到相关的PPL等级）

SeImpersonatePrivilege

微软官方解释：身份验证后模拟客户端”用户权限（SeImpersonatePrivilege）是在 Windows 2000 SP4 中首次引入的 Windows 2000 安全设置。 默认情况下，设备本地管理员组的成员和设备本地服务帐户将分配，身份验证后模拟客户端”用户权限。 以下组件还具有此用户权限：

  • 由服务控制管理器启动的服务
  • 组件对象模型 （COM） 服务器，这些服务器由 COM 基础结构启动，并且配置为在特定帐户下运行

也就是说这个权限是用来模拟用户权限操作，所有服务帐户和管理员账户都会分配这个权限，也就是说IIS 、FTP这些都会分配这个权限。
